# نودهای n8n دیدار

Community Node دیدار دو نود اصلی در اختیار شما قرار می‌دهد:

1. **Didar CRM Trigger** — برای شروع Workflow بعد از رخ‌دادن یک رویداد در دیدار، از طریق Webhook.
2. **Didar CRM** — برای اجرای عملیات مختلف روی اطلاعات دیدار؛ مثل ایجاد معامله، جستجوی شخص یا ویرایش فعالیت. این عملیات‌ها بر پایه Endpointهای Open API دیدار ساخته شده‌اند.

## Didar CRM Trigger

`Didar CRM Trigger` نود Trigger دیدار است. یعنی برخلاف نود `Didar CRM` که یک درخواست به دیدار می‌فرستد، این نود منتظر می‌ماند تا **دیدار اطلاعات یک رویداد را برای n8n ارسال کند** و با دریافت آن، Workflow را شروع می‌کند.

### کجا از این نود استفاده کنیم؟

زمانی از `Didar CRM Trigger` استفاده کنید که می‌خواهید Workflow شما **بلافاصله بعد از یک اتفاق در دیدار** اجرا شود و نمی‌خواهید n8n مرتباً از دیدار بپرسد که آیا اطلاعات جدیدی ایجاد شده یا تغییر کرده است.

برای مثال:

- بعد از ایجاد یک معامله، اطلاعات آن را به سیستم دیگری ارسال کنید.
- بعد از ایجاد یا ویرایش یک شخص، اطلاعات مخاطب را در سرویس دیگری به‌روزرسانی کنید.
- بعد از ایجاد فعالیت یا کارت، یک فرایند خودکار در n8n شروع کنید.
- بعد از ایجاد یا تغییر فاکتور، پیش‌فاکتور، محصول یا سایر موجودیت‌هایی که Webhook دارند، مراحل بعدی Workflow را اجرا کنید.

در این مدل، **Webhook دیدار نقطه شروع Workflow است** و `Didar CRM Trigger` درخواست ارسال‌شده از دیدار را دریافت می‌کند.

### این نود چطور کار می‌کند؟

فلو کلی به این شکل است:

1. نود `Didar CRM Trigger` را به ابتدای Workflow اضافه کنید.
2. داخل نود، بخش **Webhook URLs** را باز کنید.
3. URL مقصدی که n8n برای این Trigger در اختیار شما قرار داده است بردارید.
4. در دیدار یک Webhook بسازید و این URL را در فیلد **آدرس مقصد** قرار دهید.
5. نوع موجودیت و رویدادی را که می‌خواهید دنبال کنید در Webhook دیدار انتخاب کنید؛ مثلاً «ایجاد معامله».
6. از این به بعد، هر زمان آن رویداد در دیدار اتفاق بیفتد، دیدار Payload مربوط به Webhook را به URL نود ارسال می‌کند.
7. `Didar CRM Trigger` اطلاعات را دریافت می‌کند، Workflow را اجرا می‌کند و داده Webhook را در اختیار نودهای بعدی قرار می‌دهد.

<Note>
  `Didar CRM Trigger` خودش Webhook را داخل دیدار ایجاد نمی‌کند. URL دریافت را از بخش **Webhook URLs** در اختیار شما قرار می‌دهد و شما باید آن را به‌عنوان **آدرس مقصد** Webhook در دیدار ثبت کنید.
</Note>

برای آشنایی کامل با مفهوم Webhook، رویدادهای موجود، نحوه ساخت Webhook در دیدار و ساختار Payloadها، صفحه [شروع کار با وب‌هوک‌های دیدار](/start-webhook) را بخوانید.

## Didar CRM

`Didar CRM` نودی است که برای **ارسال درخواست از n8n به دیدار** استفاده می‌شود. عملیات‌های این نود بر پایه Endpointهای Open API دیدار ساخته شده‌اند.

ابتدا `Resource` را انتخاب می‌کنید؛ مثلاً Deal، Person یا Activity. سپس از بخش `Operation` مشخص می‌کنید چه کاری قرار است انجام شود؛ مثلاً Create، Update، Get یا Search.

<Note>
  در بعضی فیلدها مثل Owner، Pipeline یا Activity Type می‌توانید مقدار را از لیست انتخاب کنید یا ID را به‌صورت دستی وارد کنید. حالت دستی زمانی مناسب است که ID را از یک نود قبلی یا با Expression دریافت می‌کنید.
</Note>

  <Accordion title="Deal — معامله">
    برای ساخت، ویرایش، دریافت یا جستجوی معاملات استفاده می‌شود. معامله در دیدار برای پیگیری یک فروش مشخص از شروع تا نتیجه نهایی است.

    ### عملیات‌ها

    | Operation | کاربرد | مستندات Endpoint |
    | --- | --- | --- |
    | `Create` | ساخت معامله جدید و مشخص‌کردن شخص، شرکت، مسئول، کاریز، مرحله، مبلغ، وضعیت و محصولات | [Create Deal](/Create-Deal) |
    | `Update` | ویرایش یک معامله موجود؛ مثل تغییر مرحله، مسئول، مبلغ، وضعیت یا محصولات | [Update Deal](/Update-Deal) |
    | `Get` | دریافت اطلاعات کامل یک معامله از روی ID | [Get Deal](/Get-Deal-By-Id) |
    | `Search` | پیدا کردن معاملات با فیلترهایی مثل مخاطب، مسئول، وضعیت، کاریز، مرحله یا منبع | [Search Deals](/Search-Deal) |

    ### فیلدهای مهم

    - **Person / Company** — مشخص می‌کند معامله به کدام شخص و شرکت مربوط است.
    - **Owner** — User مسئول پیگیری معامله.
    - **Pipeline / Pipeline Stage** — کاریز و مرحله فعلی معامله. مرحله باید متعلق به همان کاریز باشد. برای دریافت IDها از [Get Deal Pipelines](/List-Deal-Pipelines) استفاده کنید.
    - **Status** — وضعیت معامله: `Pending`، `Won` یا `Lost`.
    - **Price** — مبلغ معامله.
    - **Source** — نحوه آشنایی معامله. گزینه‌ها را از [Get Sources](/Sources) دریافت کنید.
    - **Labels** — برچسب‌های معامله. گزینه‌ها را از [Get Deal Labels](/Deal-Labels) دریافت کنید.
    - **Lost Reason** — در معامله ناموفق، دلیل شکست را مشخص می‌کند. گزینه‌ها از [Get Lost Reasons](/Lost-Reasons) دریافت می‌شوند.
    - **Deal Items** — محصولات یا خدمات معامله همراه با تعداد، قیمت، تخفیف، مالیات و زیرمحصول.
    - **Custom Fields** — برای مقداردهی فیلدهای اضافه معامله؛ کلید فیلدها را از [Get Custom Fields](/Get-Custom-Fields) بگیرید.
  </Accordion>

    برای جستجوی هم‌زمان یک عبارت در چند نوع رکورد دیدار استفاده می‌شود.

    **Endpoint متناظر:** [Didaryab Search](/Didaryab-Global-Search)

    برای ارسال شماره تماس و داخلی کاربر به سرویس Caller ID دیدار و نمایش Popup تماس استفاده می‌شود.

    - **User Extension** — داخلی User دریافت‌کننده تماس.

    **Endpoint استفاده‌شده در Community Node:** `GET /api/calllog/insert`
