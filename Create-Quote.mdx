# ایجاد پیش‌فاکتور

این Endpoint برای ایجاد یک پیش‌فاکتور جدید در دیدار استفاده می‌شود. هر پیش‌فاکتور می‌تواند شامل یک یا چند ردیف محصول باشد و در صورت نیاز اطلاعات خریدار، اطلاعات فروشنده، تاریخ صدور، مدت اعتبار، تخفیف، مالیات، توضیحات و معامله مرتبط هم همراه آن ثبت شود.

در این ساختار، `SellerInfo` مربوط به کسب‌وکاری است که از دیدار استفاده می‌کند و پیش‌فاکتور را به نام خودش صادر می‌کند. `BuyerInfo` اطلاعات شخص یا شرکتی را نگه می‌دارد که پیش‌فاکتور برای او صادر می‌شود.

```http
POST {{baseURL}}/api/AccountingQuote/CreateQuote?apikey={{API_KEY}}
```

## پارامترهای Query

| پارامتر | نوع | وضعیت | توضیح |
| --- | --- | --- | --- |
| `apikey` | `string` | الزامی | کلید API دیدار. |

## Header درخواست

```text
Content-Type: application/json
```

  تعداد روزهایی است که پیش‌فاکتور از زمان صدور معتبر در نظر گرفته می‌شود.
</ParamField>

<ParamField path="Description" type="string">
  توضیحات کلی پیش‌فاکتور است و برای متنی استفاده می‌شود که مربوط به کل سند است، نه فقط یک ردیف محصول.
</ParamField>

## قواعد و محدودیت‌ها

- حداقل بدنه لازم برای ایجاد پیش‌فاکتور شامل `Items`، `CreatorId`، `BizDomainId` و `CurrencyId` است.
- داخل هر عضو `Items`، فیلدهای `Title`، `Description`، `Unit`، `UnitPrice`، `ProductId`، `ProductCode` و `Quantity` الزامی هستند.
- اگر محصول متغیر باشد، `VariantId` همان Variant انتخاب‌شده را هم ارسال کنید. برای محصول بدون Variant نیازی به `VariantId` نیست.
- مقدار `Items[].UnitPrice` همان قیمت واحدی است که برای آن ردیف محصول روی پیش‌فاکتور نمایش داده می‌شود.
- `BuyerInfo.BuyerType` فقط یکی از دو مقدار `Person` یا `Company` را می‌پذیرد.
- `BuyerEconomicCode`، `BuyerNationalCode` و `BuyerRegistrationNumber` فقط برای خریدار از نوع `Company` ارسال می‌شوند.
