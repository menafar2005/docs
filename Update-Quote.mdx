# ویرایش پیش‌فاکتور

این Endpoint برای ویرایش یک پیش‌فاکتور موجود در دیدار استفاده می‌شود. ساختار بدنه آن با ویرایش فاکتور یکسان است؛ با این تفاوت که درخواست به Endpoint مخصوص پیش‌فاکتور ارسال می‌شود. علاوه بر فیلدهای لازم برای ثبت اطلاعات سند، باید `Id` پیش‌فاکتوری را که می‌خواهید ویرایش کنید هم در بدنه درخواست ارسال کنید.

در این ساختار، `SellerInfo` مربوط به کسب‌وکاری است که از دیدار استفاده می‌کند و پیش‌فاکتور را به نام خودش صادر می‌کند. `BuyerInfo` اطلاعات شخص یا شرکتی را نگه می‌دارد که این پیش‌فاکتور برای او صادر شده است.

```http
POST {{baseURL}}/api/AccountingQuote/UpdateQuote?apikey={{API_KEY}}
```

## پارامترهای Query

| پارامتر | نوع | وضعیت | توضیح |
| --- | --- | --- | --- |
| `apikey` | `string` | الزامی | کلید API دیدار. |

## Header درخواست

```text
Content-Type: application/json
```

  توضیحات کلی پیش‌فاکتور است و برای متنی استفاده می‌شود که مربوط به کل سند است، نه فقط یک ردیف محصول.
</ParamField>

## قواعد و محدودیت‌ها

- حداقل بدنه لازم برای ویرایش پیش‌فاکتور شامل `Id`، `Items`، `CreatorId`، `BizDomainId` و `CurrencyId` است.
- `Id` باید شناسه همان پیش‌فاکتوری باشد که قصد ویرایش آن را دارید.
- داخل هر عضو `Items`، فیلدهای `Title`، `Description`، `Unit`، `UnitPrice`، `ProductId`، `ProductCode` و `Quantity` الزامی هستند.
- اگر محصول متغیر باشد، `VariantId` همان Variant انتخاب‌شده را هم ارسال کنید. برای محصول بدون Variant نیازی به `VariantId` نیست.
- مقدار `Items[].UnitPrice` همان قیمت واحدی است که برای آن ردیف محصول روی پیش‌فاکتور نمایش داده می‌شود.
- `BuyerInfo.BuyerType` فقط یکی از دو مقدار `Person` یا `Company` را می‌پذیرد.
- `BuyerEconomicCode`، `BuyerNationalCode` و `BuyerRegistrationNumber` فقط برای خریدار از نوع `Company` ارسال می‌شوند.
